## Acceptance target for this batch

Deliver the native Render workspace's end-to-end user interface for the capabilities actually implemented: model/library navigation, context-owned resource browser and inspector, scene composition, appearances, lighting, environments, camera, output, preflight, progress/cancellation and exact completed-result export. Use the existing shell, tokens, shared controls and single RENDER ribbon tab. Keep all authored catalogs inspectable, with executable projections, unbound concepts and blocked advanced capabilities identified separately.

1. Replace the long undifferentiated inspector with local Scene, Appearance, Lighting, Environment, Camera, Output and Diagnostics sections. Keep an explicit All controls view for dense expert inspection and existing interaction regressions. Never add a global expertise or render-mode system.
2. Extend the existing Browser card with a local Model/Library selector, preserving both shell layouts, selection and model visibility. Preserve per-category query/page/selection; provide bounded favorites/recent collections, availability filters and source/omission details. Original source-map previews must be labelled as source maps, not measured or path-traced material thumbnails.
3. Add reviewed native studio compositions through shared read-only resolve / atomic apply commands. Their identities are separate from unbound SCENE-* specifications. Explicit lighting/stage replacement, revision checks and conservative product clearance are mandatory. Preserve camera, appearances, engineering assignments and geometry.
4. Make fixed-sample PNG projections of compatible quality specifications explicitly opt-in. Do not turn adaptive stopping, independent transmission-depth limits, raw buffers or EXR into implemented promises. Applying a sampling budget must preserve lighting, optical bindings and camera.
5. Complete accessible numeric camera, environment, stage and output controls; pin Check/Render/Cancel/Export outside scrolling bodies. Check and Start must use the same request. Retain completed images and exact export identities across later edits and failures.
6. Add bounded shot duplication/rename/removal through the engine, with conflict rejection and one undo. Switching away from a dirty draft requires Save/Discard/Keep editing; library inspection never commits a preset.
7. Consolidate type/lint checks, focused engine/UI tests and one native application build after the coordinated changes. Inspect actual application screenshots in both themes and both layouts with a small public-safe fixture. Do not claim interaction or visual acceptance from source-only checks.

## Explicit boundaries

This UI batch does not claim adaptive sampling, a new transmission estimator, EXR/linear masters, unrestricted nested media, volumes, displacement, spectral transport, dynamics, a render queue or completed whole-project CI. Missing capabilities remain visible and cannot emit unsupported parameters. The reviewed 4K SELENE export and its renderer/model hashes remain unchanged. No new icon artwork, external assets or dependencies are required.
